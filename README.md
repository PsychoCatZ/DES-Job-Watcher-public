# DES Job Watcher — public

Очищенный публичный снимок проекта. Основная разработка продолжается отдельно в приватном репозитории. Здесь нет персональных резюме, рабочих профилей, ключей, базы вакансий и результатов реального анализа.

Python-проект персонального поиска работы на HH с анализом относительно отдельных резюме. Основной упор — два направления с рабочим опытом:

- письменная и техническая поддержка;
- разметка данных и оценка качества ИИ.

Разработка, AI-интеграции и автоматизация — дополнительное направление, которое включается явно. Уроки сопровождают разработку и не требуют отдельного прохождения перед следующим рабочим шагом.

Проект развивается небольшими работающими шагами вместе с уроками. Автор определяет требования, проверяет решения и изучает Python; AI-агент помогает проектировать, писать и проверять код. Реализованы часовой поиск, постоянная очередь и управление через Telegram. Проект продолжает развиваться; качество подбора требует проверки пользователем.

## Что уже работает

- Учебный поиск на вымышленных данных; отдельные сетевые примеры HH с явным включением.
- Подготовка входа из одного профиля и полного описания вакансии.
- Версионированные правила, инструкции и JSON-контракт ответа.
- Один анализ через OpenAI Responses и последовательный прогон корпуса без автоматических повторов.
- Проверка структуры ответа, существования цитат и ссылок на опыт.
- Отдельные решения о соответствии и маршруте показа: `show`, `review`, `exclude`.
- Локальный пересчёт правил по сохранённым ответам, отчёты и модульные тесты.

SQLite-история карточек и версий, сохранение оценок и локальные Markdown-отчёты реализованы. Telegram поддерживает привязку личного чата и доставку одной карточки с учётом прежних попыток. Часовой сбор с очередью и кнопки управления реализованы в публичном коде. Состояние «просмотрено человеком» пока не реализовано. Для самостоятельного развёртывания есть шаблон systemd-службы; работа конкретного развёрнутого экземпляра здесь не подтверждается. Регистрация приложения HH одобрена. Официальный API-клиент и запуск `python -m examples.collect_hh --live` подготовлены: поддержка и AI-data по умолчанию, первая страница каждого запроса, дедупликация ID внутри запуска и локальный отчёт. Это кандидаты из поиска, ещё без оценки полных описаний. Первый токен можно получить через `--issue-token`; ввод скрыт, значения остаются в памяти. Подробности — в уроке 17. HTML-пример остаётся экспериментом.

`python -m examples.run_once` показывает план без сети. С `--live` выполняется ограниченный проход: поиск, объяснимый приоритет кандидатов, полные карточки, Luna и общий отчёт. Флаг `--telegram` добавляет отправку не более одной неотправленной карточки для рассмотрения в заранее привязанный чат. Требуются переменные текущего окна из `scripts/start_session.ps1`. Предварительный отбор — эвристика по задачам; отложенные кандидаты сохраняются в аудите. Изменённые вакансии пока не создают повторных уведомлений. Локальная проверка отбора не подтверждает качество нового живого анализа.

Часовые раскопки запускаются через `python -m examples.control_telegram --live --schedule`. Они используют `examples.run_queue`: уникальные ID сохраняются в SQLite, остаток переносится на следующий проход. По умолчанию поиск берёт до 50 позиций на страницу и при нехватке кандидатов просматривает до трёх страниц на поисковую фразу. Параметры `--page-size`, `--max-pages` и `--analysis-limit 10|20|30` управляют объёмом. Лимит анализа общий для двух профилей и учитывает все попытки Luna. В Telegram отправляются вакансии, которые Luna считает подходящими или предлагает рассмотреть. Часовой проход запрашивает отдельное поле model_verdict (инструкция 10). Если проверка ответа не прошла, читаемый положительный вывод Luna показывается с пометкой. Остальные попытки остаются в отчёте. Каждая рекомендация отправляется отдельной карточкой, сильные совпадения в начале. Полные результаты доступны в общем отчёте. Счётчики прохода выводятся в терминале и сохраняются в `run_stats.md` и `run_stats.json` рядом с отчётом.

## Правила оценки

Задачи вакансии сопоставляются с фактами выбранного резюме. Опыт разработки с AI-инструментами учитывается как практический опыт; он не заменяет отсутствующую предметную квалификацию. Зарплата, график и занятость — информация для пользователя, без снижения оценки.

Явно обязательный голос или видеовстречи без полноценной письменной альтернативы — препятствие. Неизвестный канал общения нейтрален. Неизвестный навык не означает, что кандидат им не владеет. Профессиональные сомнения не должны скрывать вакансию от пользователя.

Это персональная конфигурация правил, а не универсальная модель отбора кандидатов. Точность смысловых выводов модели не гарантируется проверкой JSON или цитат.

## Быстрый запуск без ключей и сети

Python 3.12, команды из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe examples\search_hh.py
.\.venv\Scripts\python.exe -m examples.validate_analysis --demo
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Сетевой доступ нужен для первоначальной установки HTTPX. Приведённые примеры и тесты сами API не вызывают.

Для работы с вымышленными профилями:

```powershell
.\.venv\Scripts\python.exe -m examples.setup_demo_profiles
.\.venv\Scripts\python.exe -m examples.run_evaluation --manifest examples/fixtures/evaluation/cases.json --profile-directory config/profile_examples --synthetic
```

Первая команда создаёт три **вымышленных** профиля в игнорируемой папке `config/profiles`. Она откажется заменять существующие файлы. Вторая явно использует учебные профили из `config/profile_examples` и синтетический режим, только проверяет сборку девяти вымышленных вакансий, без обращения к модели. Для второй команды предварительное копирование профилей не требуется. Учебные профили не описывают реального человека и не должны использоваться для персональных рекомендаций. Обычный режим откажется отправлять явно помеченный синтетический профиль; флаг не может включиться из текста вакансии.

Для реальной работы нужны собственные профили с источниками и отдельный локальный корпус. Публичные шаблоны не заменяют извлечение и проверку своего резюме. Личные данные и результаты отсутствуют в репозитории.

## Ключи и реальные запросы

Ключ OpenAI передаётся через временную переменную окружения. `scripts/run_openai.ps1 -InputPath <путь-к-входу>` запрашивает ключ с маскировкой и выполняет один платный вызов. `scripts/run_evaluation.ps1` предназначен для локального личного корпуса и делает до одного запроса на случай. До ввода ключа выполняется проверка сборки.

`--live` явно включает сеть; не используйте его для обычных тестов. При ошибке повторов нет. Таймаут не доказывает, что сервер не обработал запрос. Ключи, токены, реальные резюме и журналы в Git не добавляются. Внешнему LLM передаётся выбранный текст профиля и вакансии: состав данных нужно проверять до реального запуска.

## Структура

| Путь | Назначение |
| --- | --- |
| `des_job_watcher/` | Проверка ответов, сборка запроса, API-адаптер и исполнитель корпуса |
| `examples/` | Небольшие запускаемые сценарии |
| `config/profile_examples/` | Только вымышленные учебные профили |
| `config/profiles/` | Личные профили, локально, исключены из Git |
| `config/contracts/`, `config/rules/`, `prompts/` | История схем, правил и инструкций |
| `tests/` | Проверки на вымышленных данных |
| `docs/lessons/` | Открытые версии уроков |
| `data/` | Локальные входы и результаты, исключены из Git |

Новые обычные анализы: правила 3, дополнительная политика 2, инструкция 9, контракт 4, политика оценки 4. Инструкция объединяет стационарные компьютеры и ноутбуки в категорию ПК, а телефоны и планшеты — в категорию мобильных устройств. Явное требование к ОС сопоставляется с подтверждёнными фактами кандидата. Исторические примеры и замороженное сравнение сохраняют инструкцию 5 и контракт 3. Синтетические профили версии 2; режим фиксируется отдельно в метаданных запроса и отчёте.

«Копнуть один раз» запускает одну партию и автоматически выключает раскопки
после сообщения «Раскопки закончены», даже если рекомендаций нет.
«Начать раскопки» сохраняет режим работы по расписанию.

Кнопка «Обновить поиск» пропускает необработанный остаток очереди и сохраняет
его ID с отметкой ручного пропуска. История анализов и доставок не сбрасывается.
При включённых раскопках новый запрос HH начинается после завершения уже
отправленного запроса и старого прохода; при выключенных — после включения.

## Развёртывание на VPS

Шаблон службы: `deploy/des-job-watcher.service`. Он предполагает отдельного пользователя `des-watcher`, папку `/opt/des-job-watcher` и установленное виртуальное окружение. Подготовьте их перед активацией. Секреты службы хранятся отдельно от репозитория в `/etc/des-job-watcher/credentials.json` и передаются через systemd credentials.

После подготовки сервера и собственных профилей используйте `scripts/activate_vps.ps1 -SshHost <ваш-SSH-псевдоним>`. Скрипт проверяет API до запуска службы. Не запускайте одновременно два контроллера одного бота.
