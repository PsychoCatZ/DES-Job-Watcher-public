# 33. Приоритет кандидатов перед платным анализом

Поиск по словам не устанавливает основную работу: разметка страниц в SEO не
равна аннотированию датасетов. `candidate_selection` использует название и
сниппет обязанностей для предварительного приоритета отдельно по профилям.
Проверка навыков, обязательности условий и соответствия резюме остаётся Luna.

Прямой признак задачи в названии даёт 10 баллов, в обязанностях — 3. Совпадения
считаются по группам регулярных выражений. Сортировка стабильная: при равном
балле сохраняется порядок исходной выдачи. Это прозрачная эвристика, не
вероятность соответствия и не копия алгоритма HH. Зарплата, график и перечисление
технологий в требованиях не влияют на баллы.

Явно посторонние роли (например, рекрутер или SEO-специалист) без прямого признака
целевой роли в названии исключаются из этой партии. Data Light исключается
по точному нормализованному имени. Управленческие роли откладываются. Упоминание
звонков в названии поддержки снижает приоритет, но не устанавливает обязательный
голос. Пустые и неясные признаки дают `defer`, а не отказ в профессиональной
пригодности. Все кандидаты сохраняются в исходном поиске.

`select_candidates(records, profile, limit)` возвращает два списка: выбранные
записи и аудит всех рассмотренных пар с баллами и причинами. `clean` удаляет
HTML-подсветку HH и нормализует пробелы и регистр. `re.search` ищет смысловые
основы слов; регулярные выражения не понимают весь контекст и отрицания.

В общем проходе после поиска создаются `selected_support.json` и
`selected_ai_data.json`. Один и тот же выбранный список передаётся загрузке
карточек и анализу. Анализ может пропускать уже оплаченные попытки, архив,
исключённого работодателя и известные барьеры; вакансии вне списка не подставляются.
Если выбранная карточка уже есть в SQLite, загрузка использует прежнее поведение
кэша. Обновление кэша и версии доставки этим изменением не реализованы.

Локальная проверка без сети:

```powershell
.\.venv\Scripts\python.exe -m examples.select_candidates --input <candidates.json> --profile support --limit 2 --output <новый-файл.json>
```

Выходной файл создаётся без перезаписи существующего. Можно проверить отложенные
и исключённые записи по `selection_audit`. Автоматического добора отложенных
вакансий нет: эвристика может пропустить необычное описание. Полнота поиска
ещё требует оценки на независимых примерах и проверки пользователем.

На сохранённой выдаче из 116 ID проверены оба профиля без HH и Luna. Первые
выбранные роли относятся к поддержке и разметке/промптам вместо рекрутера и
руководителя органического трафика. Это проверка предварительного отбора,
не подтверждение соответствия полным требованиям или текущей доступности.

Следующая рабочая точка: проверить выбранные полные тексты, затем ограниченный
реальный проход; после качества отбора — кнопки начала/остановки фонового поиска.
