# 31. Постоянная привязка личного чата

`python -m examples.send_telegram --bind-only --live` выполняет привязку без
отправки вакансии. Токен вводится со звёздочками или берётся из окружения.
Одноразовая команда подтверждает личный чат. В `data/telegram_binding.json`
сохраняются только ID бота и чата, без токена. Файл исключён из Git вместе с data.
Если привязка уже существует, повторный код не нужен; другой бот вызывает ошибку,
а существующая привязка автоматически не перезаписывается.

При отправке `--report <папка> --live` функция `next_card` выбирает первую карточку
для рассмотрения, для которой нет записи о попытке доставки. За один запуск
отправляется не более одной карточки. Ключи прежних записей сохранены: уже
доставленная тестовая вакансия повторно не отправляется. Профессиональный разбор
не отправляется этим сценарием автоматически; отдельная подборка ещё впереди.

`load_binding` возвращает `None`, если файла нет. Это отличается от ошибки чтения:
повреждённый файл или несовпадение бота останавливают запуск, а не создают новую
привязку молча. Режим `open('x')` защищает существующий файл от замены.

Файл попытки резервируется до отправки. И успешная, и незавершённая попытка
блокируют повтор. Это не гарантия exactly-once: при обрыве связи невозможно
узнать по одному таймауту, доставлено сообщение или нет. Требуется отдельный
разбор такого случая, а не автоматическая повторная отправка.

Изменения вакансий пока не создают новую доставку: ключ по-прежнему использует
бота, чат, ID вакансии и профиль. Проверку актуальности старых результатов и
версионные уведомления этот шаг не добавляет. Без `--live` показывается только
пример из отчёта, без фильтрации по получателю и истории доставки.
