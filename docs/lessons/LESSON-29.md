# 29. Карточка уведомления перед подключением Telegram

`notification_card.render_notification(card, review)` получает описание карточки из
`summary.json` и её отдельный JSON с оценкой. Функция возвращает строку: сеть,
ключи и база ей не нужны. Благодаря этому текст можно проверить до отправки.

`card` содержит название, профиль и ID вакансии. `review['assessment']` содержит
решение, маршрут и анализ. Проверка пары ID–профиль не позволяет случайно соединить
название одной вакансии с объяснением другой.

Словари в Python позволяют обращаться к именованным полям: `work['summary']`.
Метод `get('readiness_reason')` возвращает значение необязательного поля или `None`.
Функция `compact` сокращает длинные поля; полный разбор сохраняется в отчёте.
`'\n'.join(lines)` соединяет список строк в одно сообщение с переносами.

Решение и маршрут используются вместе. `clarify/show` не превращается в уверенное
«подходит». Неподтверждённые условия остаются вопросами. Зарплата и график не
участвуют в формировании вердикта. Старый анализ явно помечен: свежесть вакансии
при предпросмотре не проверяется.

Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m examples.preview_notifications --report <папка-отчёта>
```

По умолчанию показываются карточки для рассмотрения. `--include-review` добавляет
профессиональный разбор; исключённые вакансии не входят в этот предпросмотр.
Команда только читает файлы и выводит текст. Транспорт Telegram и учёт доставки
подключаются отдельным шагом.
