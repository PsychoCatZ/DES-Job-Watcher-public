# 30. Первая отправка в Telegram

`examples.send_telegram` читает первую карточку группы `consider` из выбранного
отчёта. Без `--live` это только предпросмотр. С `--live` токен читается из
`TELEGRAM_BOT_TOKEN` или вводится со звёздочками через `read_secret`.

Программа генерирует случайную команду `/start <код>`. Пользователь отправляет её
своему боту и нажимает Enter в терминале. `getUpdates` возвращает JSON обновлений;
мы ищем точное совпадение команды только в личном чате, где ID отправителя совпадает
с ID чата. Чужие команды и группы не выбираются. Обновления не сохраняются в файлы.
Если команда не найдена, сценарий завершается; следующий запуск выдаёт новый код.
Это временная привязка для первой проверки, не постоянный обработчик команд.

`TelegramClient` использует один `httpx.Client`. Метод `call` отправляет POST с JSON,
проверяет HTTP-статус и поле `ok`. Сетевое исключение превращается в `TelegramError`
без URL: в URL Telegram присутствует токен. Повторов нет. Redirect не разрешён.
Отправка выполняется методом `sendMessage`, без интерпретации разметки и превью ссылки.

До отправки создаётся файл в `data/telegram_deliveries` с режимом `open('x')`:
он отказывается перезаписывать существующий файл. Ключ зависит от бота, чата,
ID вакансии и профиля. Токен в файл не записывается. После подтверждения API
статус меняется на `sent`, сохраняется ID сообщения. При сбое статус остаётся
неопределённым и повтор блокируется. Это защита одной ручной доставки;
изменённые вакансии, постоянная привязка, расписание и команды бота ещё впереди.

Проверки с `MockTransport` не обращаются к Telegram: проверяют выбор личного чата,
отсутствие токена в сообщении об ошибке, отсутствие повтора и ограничение длины.
Реальную доставку и отображение подтверждаем отдельно в личном чате.

Документация: https://core.telegram.org/bots/api#getupdates и
https://core.telegram.org/bots/api#sendmessage.
