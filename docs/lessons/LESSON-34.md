# 34. Ручное обновление поиска без потери истории

Остаток очереди не обязан иметь ту же полезность, что первые кандидаты. При
этом один проход без рекомендаций не доказывает бесполезность всех оставшихся
вакансий. Кнопка «Обновить поиск» даёт пользователю возможность пропустить
остаток и заново получить выдачу HH по соответствию.

`DigControl.accept` сохраняет команду в SQLite: `refresh_request` содержит
номер запроса, а увеличение `generation` запрещает старому проходу начинать
следующие сетевые операции. Уже отправленный запрос завершается, результат
сохраняется. Состояние включённых или выключенных раскопок не меняется.

Контроллер продолжает принимать команды и вызывает `apply_refresh`. Пока
дочерний процесс работает (`worker.poll() is None`), функция возвращает `None`.
После его завершения можно безопасно изменить остаток очереди. Здесь `None`
означает «обновление ещё не выполнено», а число `0` — «выполнено, очередь пуста».
Поэтому проверяется `is not None`, а не просто истинность результата.

`VacancyQueue.dismiss_pending` меняет только статус `pending` на `dismissed`.
Строки и их ID сохраняются: `INSERT OR IGNORE` не позволит новому поиску сразу
вернуть пропущенные вакансии в очередь. История анализов, результаты и отметки
доставки не удаляются. Это ручной пропуск ID, а не оценка «не подходит».

Изменение статусов и запись в `queue_refreshes` происходят в одной транзакции.
Номер запроса уникален. Если процесс завершился после изменения очереди, но до
снятия команды в другой базе, повторное выполнение вернёт сохранённый счётчик,
не затронув новых кандидатов. Такая операция называется идемпотентной.

При включённых раскопках контроллер обнуляет время ожидания и запускает новый
проход с первой страницы HH. При выключенных ждёт кнопки «Начать раскопки».
Свежий запрос не гарантирует новых подходящих вакансий: HH может вернуть
те же ID, которые будут пропущены по сохранённой истории.

Проверки без сети:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_refresh_search -v
```

Тесты проверяют ожидание работающего процесса, смену поколения, сохранение
обработанных записей, защиту от чужих и повторных команд, восстановление
отложенного обновления после рестарта и миграцию существующей базы управления.
